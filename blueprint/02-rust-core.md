# Xryloth — Rust Core Internals (`src-tauri/src/lib.rs`)

`lib.rs` is a **single 11,944-line file** containing the whole backend: constants, helpers, 174 Tauri commands, the AI agent, the server manager, and `run()`. This document covers the *infrastructure* half (everything that isn't covered topic-by-topic in `03`–`12`). Line refs exact.

## 3. HTTP layer

### 3.1 Cache — `http_get_cached` (83-102)

`static HTTP_CACHE: OnceLock<Mutex<HashMap<String,(u64, Value)>>>` (76) keyed by URL, **600 s TTL**. Used for version manifests, Java-version lookups, etc.

> ⚠️ **Dead field**: `AppState.http_cache` (234, initialized 255) is never read — the real cache is the static. Don't rebuild both.

### 3.2 Primitives (360-499)

| fn | line | behavior |
|---|---|---|
| `is_connected()` | 364 | `HEAD https://sessionserver.mojang.com`, **2 s** timeout, **10 s** cached result. Drives online/offline auth decisions. |
| `http_get(url, headers)` | 380 | blocking reqwest, UA + **30 s** timeout, JSON parse |
| `http_get_async` | 398 | async twin |
| `http_post_json(url, body, headers)` | 414 | JSON POST |
| `http_post_form(url, form, auth)` | 431 | `application/x-www-form-urlencoded` (OAuth exchanges) |
| `download_file_blocking(url, dest)` | 449 | **120 s** timeout, streams to disk, no checksum |
| `download_file_progress(url, dest, cb)` | 466 | **600 s** timeout, `cb(done,total)` for progress events |

All use `USER_AGENT = "Xryloth/5.0"`. **No SHA1/SHA256 verification anywhere** — existence + non-empty is the only integrity check (see `05-launch-pipeline.md` gotcha #3).

### 3.3 Maven helper — `maven_name_to_path` (501-513)

`group:artifact:version[:classifier]` → `group/as/slashes/artifact/version/artifact-version[-classifier].jar`. Used to place Fabric/Quilt profile libraries.

## 4. Version helpers (515-552)

- `parse_version_tuple(ver) → (i32,i32,i32)` (516) — tolerant of missing parts.
- `loader_supports(loader, ver)` (524) — vanilla always; fabric/quilt ≥1.14.0; forge ≥1.4.0; neoforge ≥1.20.2; optifine ≥1.7.0.
- `build_version_groups(&[String])` (536) — buckets versions by `^(\d+\.\d+)` regex into `HashMap<group, Vec<ver>>`, each group sorted newest-first. Powers the version picker's grouped dropdown.

## 5. Settings & instances storage (553-599)

```rust
load_settings(app)      // 553: reads AppState.settings; loads settings.json once when empty, returns clone
get_setting_val(s,k,d)  // 568
save_setting_val(app,k,v) // 572: insert + rewrite whole settings.json (pretty JSON)
load_instances_raw(app) // 578: instances.json + adds `installed`, `version_json_exists`
save_instances(&[..])   // 596: rewrite instances.json
```

`load_json(path)` / `save_json(path, val)` (295-310): read → `Value::Null` on error; write → pretty-print, create parent dirs, **errors ignored**.

> Pattern note: every write rewrites the **entire file** (no locking beyond the `Mutex`). Two processes writing concurrently can clobber — mitigated only by single-instance.

## 6. Logging (312-328)

- `log_msg(app, msg)` → `[HH:MM:SS] msg` pushed to `AppState.log_entries` (**cap 5000**, drop-oldest) + `println!`.
- `append_game_output(app, line)` → `AppState.game_output` (**cap 500**).
- Both are polled by `get_logs` / `get_game_output` — no event per line for the launcher log.

## 7. Process helpers (330-358)

- `hidden_cmd(program)` (331) — on Windows adds `CREATE_NO_WINDOW` (`0x08000000`) so no console flashes.

## 9. Discord RPC (105-219, commands 4441-4703)

Hand-rolled Discord IPC (no crate):

- **Transport** `discord_connect(index)` (117): Windows named pipe `\\.\pipe\discord-ipc-{0..9}`; Unix domain socket `$XDG_RUNTIME_DIR/discord-ipc-N` / `/tmp/discord-ipc-N` (105-110).
- **Framing** `discord_ipc_frame(opcode, payload)` (144): `[u32 opcode][u32 len][utf8 json]` LE.
- **`discord_set_activity`** (164): builds `{"cmd":"SET_ACTIVITY","nonce":…,"args":{"pid":…,"activity":{details,state,assets{large_image,large_text,small_image,small_text}}}}`, opcode 1.
- `DiscordRpcHandle { sender: mpsc::Sender<DiscordMessage> }` (216) — a writer thread owns the socket; commands push messages.
- Commands: `init_discord_rpc` (4441, spawn writer + handshake HELLO/READY), `update_discord_rpc` (4650), `stop_discord_rpc` (4679), `get_discord_status` (4691).
- Auto-init at boot if `settings.discord_rpc` (run() 11898-11911); `launch_game` flips activity to "Playing Minecraft …" on start and "Browsing Xryloth" on exit (2330-2419).

## 10. System info (3235-3409)

`get_system_info()` → `{cpu, ram_used, ram_total, ram_pct, …}`:

- **Windows**: `wmic` (CPU load + `FreePhysicalMemory`/`TotalVisibleMemorySize`) executed on a background thread with an **mpsc 5 s timeout** — comment explains wmic is deprecated and can block 30 s+ (3243-3250).
- **Linux**: `/proc/meminfo` for RAM, `df` for disk, `/proc/stat`-style CPU sampling (3316+).
- **macOS**: `vm_stat` parsing (3364+), fallback leaves used/pct at 0.

## 11. Updater internals (3110-3233)

- `updates_dir()` = `~/.xryloth/updates/`.
- **`asset_score(name)` (3123-3148)** — platform-specific scoring of GitHub release assets:
  - Windows: `.exe` with `setup`/`install` → **100** (installer preferred over portable), other `.exe` lower, `.msi` next…
  - Linux: **AppImage and portable `.exe` are rejected**; `.deb` (lowercase rule) preferred
  - macOS: `.dmg`
  Used both to pick the download and as a guard in the version comparison.
- `release_info()` — GitHub `releases/latest`, parses tag title, strips leading `v`, compares against `APP_DISPLAY_VERSION` (4-part numeric compare `version_gt` at 3091).
- Commands: `check_updates` (3226, old thin wrapper) and `check_launcher_update` (10564) / `download_update` (10642, progress events) / `install_update` (10676, platform apply: run setup exe detached on Windows; stage-and-replace AppImage/binary elsewhere). Full flow: `11-build-release.md`.

## 13. Boot sequence — `run()` (11736-11944)

1. **Migrate** `~/.eclauncher` → `~/.xryloth` if new dir absent (11738-11751).
2. `ensure_dirs()` (11752) — creates `~/.xryloth`, `instances/`, `libraries/`, `assets/{indexes,objects}`, `servers/` (285-293).
3. `claim_single_instance(takeover_from_flag)` (11757) → `Owner(listener)` / `HandedOff` / `Unavailable` (§14).
4. `tauri::Builder::default().manage(AppState::new()).invoke_handler(generate_handler![…174…])` (11769-11842).
5. `.setup()` (11844+):
   - spawn single-instance TCP server thread (`serve_single_instance`)
   - `window.set_title("Xryloth")`
   - **asset-protocol scope**: `scope.allow_directory(app_dir(), true)` — the static `assetScope ["**"]` in tauri.conf.json doesn't match absolute home paths under Tauri 1.x glob semantics (11853-11864)
   - `present_running_window()` — X11 `_NET_ACTIVE_WINDOW` activation (11717), retried once after ~1.5 s
   - Discord RPC auto-init after 2 s if `discord_rpc` enabled (11898)
   - **auto-start local servers** with `start_on_launch: true` after 4 s (11913-11938)
6. `run(tauri::generate_context!())`.

`main.rs` forces `GDK_BACKEND=x11` (unless the user set it) because all window activation uses Xlib.

## 14. Single instance (11243-11734)

Loopback TCP **`127.0.0.1:51543`** (11260) with greeting verbs:

| const | value | meaning |
|---|---|---|
| `SINGLE_INSTANCE_PRESENT` | `xryloth-present` | "are you there?" → focus the window |
| `SINGLE_INSTANCE_TAKEOVER` | `xryloth-takeover` | "the updater restarted me — take over" |
| `SINGLE_INSTANCE_TAKEOVER_FLAG` | `--xryloth-takeover` | argv flag passed by the updater (11265) |

`claim_single_instance` (11353): try to connect → if a healthy peer answers, send the verb and return `HandedOff` (exit 0); else bind the listener and return `Owner`; if the port is occupied by something that doesn't answer the greeting, start anyway (`Unavailable`) — deliberate so a stray program can't block launch (comment11254-11257). The listener thread handles `present` (activate window) and `takeover` (swap ownership).

Why it exists (comment 11244-11253): the installer, updater, desktop icon and second clicks all relaunch the app within seconds; two copies shared a WM_CLASS so the taskbar showed one button that "minimised itself".

## 15. Cross-cutting patterns & gotchas

1. **One giant file** — no modules. For a rebuild, split by the section headers above; the boundaries are already clean.
2. **`Value`-typed everything** — no serde response structs; the contract is implicit. Consider generating TS types from Rust in your rebuild.
3. **Blocking-in-async discipline** — `#[tauri::command(async)]` + `tokio::task::block_in_place` + `std::thread::spawn` / `spawn_blocking` is used consistently so the event loop never stalls (comment at 7019-7022 explains why: reqwest blocking owns a runtime that must not be dropped on an async worker).
4. **Errors are JSON values**, not `Result::Err` (except `ai_chat`, `uninstall_launcher`).
5. **No file locking** — every JSON write rewrites the whole file; single-instance is the only concurrency guard.
6. **No download checksums** — see `05-launch-pipeline.md`.
7. **Secrets in source**: `ELYBY_CLIENT_SECRET` (46) is plaintext; Groq/Gemini keys are compile-time embedded (better, but extractable from the binary).
8. **Dead code**: `AppState.http_cache` (234) never read; `check_updates` (3226) superseded by `check_launcher_update` (10564).
9. **Windows-first assumptions** surface in natives (`get_native_artifact`), managed Java (`bin/java.exe`), and boost steps — audit every `cfg(target_os)` before shipping cross-platform.
