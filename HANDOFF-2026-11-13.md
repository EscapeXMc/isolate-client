## 3. Ely.by OAuth — "Redirect URI is invalid" ERROR + FIX (verified from their source)

### The error (reported 12 Nov)
While registering the app on ely.by, both `http://localhost:8080/callback` and `http://127.0.0.1:8080/callback` are rejected with **"Redirect URI is invalid"**.

### Root cause (read from ely.by's actual code — git.psf.lt/ElyBy-Mirror/accounts)
`common/components/OAuth2/RedirectUriRules.php`:

- **`canBeRegisteredAsWebApplication()`** (used when app type = **Website**): explicitly **REJECTS all loopback hosts** — `localhost`, `[::1]`, `*.localhost`, `127.x.x.x` → that's why the form errors. Their comment says: *"neither custom schemes nor loopback addresses are allowed, native applications should be registered as the **desktop** ones."*
- **`isAllowedForDesktopApplication()`** (app type = **Desktop application**): http/https **allowed ONLY for loopback hosts**; custom URI schemes also allowed (RFC 8252).
- At auth time (`isMatchingRegisteredRedirectUri`) loopback gets **any-port matching** (RFC 8252 §7.3) → port 8080 fine.

### ✅ FIX (done 12 Nov)
1. App created on https://account.ely.by/dev/applications/new as **"Desktop application"** type (Website type rejects loopback — that was the error)
2. Redirect URI: `http://127.0.0.1:8080/callback`
3. **SAVED in `src-tauri/src/lib.rs:2630`:**
   - `ELYBY_CLIENT_ID = "isolate-client1"` ✅
   - `ELYBY_CLIENT_SECRET = ""` ✅ (desktop apps get no secret; token exchange runs as public client, lib.rs:2787)
4. Saving this lib.rs edit auto-restarts `tauri dev` — **clicks are dead during the ~20s rebuild** (this is expected; user hit it once). Wait for `[Isolate] Ready` in the log.
5. **TODO:** end-to-end sign-in test from Accounts page (not yet run).

### Flow reference (code)
`ELYBY_REDIRECT_URI` at `src-tauri/src/lib.rs:2632`. Local callback server on 127.0.0.1:8080 (started by `authenticate_elyby`, lib.rs:2681). Flow: authorize `https://account.ely.by/oauth2/authorize` → local callback → `poll_elyby_auth` → code exchange at `…/api/oauth2/v1/token` → account info via `…/api/account/v1/info`.
